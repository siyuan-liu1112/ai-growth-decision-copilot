# 后续路线：未实现能力与验收标准

这些是原流程设计及后续讨论中的扩展，不代表已有代码能力，也不是上线时间承诺。

| 优先级 | 尚未实现 | 验收标准 |
|---|---|---|
| P1 | 真实模型生成、审查、改进、综合复核 | 服务端调用；结构校验、来源引用、超时及失败状态；不在前端保存密钥 |
| P1 | 完整目标与上下文输入 | 支持产品描述、当前策略、目标指标、偏好；不把所有业务强制套入14天复参与 |
| P1 | 语义去重与多样性 | 能识别措辞不同但干预相同的方案，并展示合并理由 |
| P1 | 独立pairwise tournament | 保存对阵、理由、并列及稳定性结果；区别于同一分数的比较 |
| P1 | 更完整质量门槛 | 覆盖相似度、隐私、证据、排序不稳及改进无效；缺少阈值时不虚构 |
| P1 | 真正定向迭代编排 | 问题返回对应角色，保留输入/输出版本；最多额外一轮并报告剩余问题 |
| P2 | 示例体验 / 我的任务独立入口 | 首次访问可一键体验示例；示例不会混入用户业务记录 |
| P2 | 数据导入及可信来源管理 | schema校验、记录来源与日期、缺失值提示、拒绝错误口径 |
| P2 | 云端保存与账户 | 跨设备恢复、用户隔离、导出及删除；当前浏览器存储仍明确标识 |
| P2 | 真实用户试用与反馈 | 目标用户能独立完成创建到理解推荐；记录任务完成情况与困惑，不预填成功率 |
| P3 | 实验执行后的结果回填 | 处理/对照人数、14天结果、成本、退订、观察完整性；区分随机与观察研究 |
| P3 | 更新证据并用于下轮决策 | 保存来源和版本，说明哪些建议改变及为什么；允许结果不确定 |

## 不混淆两个环节

Evolution是执行前改进方案。结果回填和更新证据是执行后的长期反馈闭环。两者可以并存，但不能互相替代。

## 评估计划（尚未开展）

比较单次生成与完整流程的方案质量、证据可追溯性、硬约束违规率、结果稳定性、响应时间及调用成本。由明确评分标准和人工复核评估；不预先宣称多Agent优于单模型。

## 当前不做

自动发送营销消息、自动开展实验、无边界无限迭代、自动训练模型、未经核验的因果收益或收入ROI承诺。
